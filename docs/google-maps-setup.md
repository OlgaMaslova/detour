# Google Maps setup

Detour's two maps — the city board (`#venue-map`) and the place locator
(`.place-map` / `.detail-locator-map`) — have two possible providers. All of the
map code lives in [`src/maps.ts`](../src/maps.ts); main.ts only says where a map
goes and what happens when a pin is pressed.

**With `VITE_GOOGLE_MAPS_API_KEY` set, the maps are Google's. Without it they are
Leaflet over OpenStreetMap tiles**, which needs no key, no account and no card.
The choice is made once at module load and the exported functions are identical
either way, so nothing outside `maps.ts` knows which is running.

That fallback is why a fresh checkout gets working maps rather than empty frames,
and it is also the reason the tape tint still exists: filtering OSM tiles only
recolours streets, so `--tape-map-filter` still applies on that path. Google draws
its logo and required attribution into the same canvas, so there the palette has
to be a cloud style instead — see below.

Leaflet is imported dynamically, so a keyed production bundle never fetches the
library. The chunk is still emitted; no browser with a key requests it.

## What to create

1. **A Google Cloud project with billing enabled.** Required even to stay inside
   the free allowance.
2. **Enable the Maps JavaScript API** for that project.
3. **An API key**, restricted two ways:
   - *Application restriction:* HTTP referrers — `takedetour.app/*` and
     `*.takedetour.app/*`. The key ships in the client bundle, so the referrer
     restriction is what actually protects it.
   - *API restriction:* Maps JavaScript API only.
4. **A map ID** (Map management → Create map ID), type **JavaScript / Vector**,
   with a **map style** attached to it.

Step 4 can wait: with a key and no map ID the code falls back to Google's
`DEMO_MAP_ID` and the maps draw with working pins in Google's own colours. That
demo ID is tied to a fixed reduced-POI style and cannot carry a style of yours,
so the tape palette needs a real map ID eventually.

## Working locally without a billing account

Steps 1–3 can also wait, for local work only. Google issues a
[Maps Demo Key](https://developers.google.com/maps/documentation/javascript/demo-key):
no-cost, no billing information, generated by signing in and pressing a button.
It covers the Maps JavaScript API and markers, which is everything this app
draws, and reaching its daily limit pauses usage until the next day rather than
charging anything.

A demo key is an ordinary key string as far as this code is concerned. Put it in
`.env`, alongside the local API URL:

```
VITE_GOOGLE_MAPS_API_KEY=…
```

It is not a way to ship. Google states the demo key is for testing and
prototyping only and is not designed for production use, and a daily-cap pause
would break the live site's maps until the following day. Production needs
steps 1–3 — or billing added to the demo key itself, which is the other route
Google offers.

**The Leaflet fallback will not rescue that**, and it is worth being clear about
why. The provider is chosen once, from whether a key exists — not from whether
Google then works. A key that is present but throttled, rejected or misrestricted
gets Google's own error state, not OpenStreetMap tiles. The fallback covers an
unconfigured checkout, which is a build-time fact; it is not a runtime failover.

## Where the production key lives

Not in `.env.production`. That file is tracked, so a key in it is a key that has
to be rotated out of git history rather than out of a settings page.

Both values are repository secrets instead, read by the build step in
[`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml) — Settings →
Secrets and variables → Actions:

```
VITE_GOOGLE_MAPS_API_KEY
VITE_GOOGLE_MAPS_MAP_ID
```

CI warns, without failing, when either is missing, and says which provider the
build shipped. Neither state is worth blocking a release that is about something
else — a keyless production build still serves working maps, just the development
provider — but shipping the fallback by accident is worth being told about.

This is a browser key and is readable in the shipped bundle no matter where it
comes from. What protects it is the HTTP referrer restriction on the key itself,
which is why step 3 is not optional in production.

## Making a bill impossible

Ordinary traffic will not reach the free allowance — see *Cost* below for why. The
things that would are a bug mounting maps in a loop and someone spoofing the
referrer to spend your quota.

Against both, set a **daily quota cap** on the Maps JavaScript API in the Cloud
console (APIs & Services → Maps JavaScript API → Quotas) at roughly **330 map
loads per day**, which is the free monthly allowance divided across a month.

A cap and a budget alert are not the same tool. An alert emails you after the
money is spent; a cap makes the API refuse the request, so thirty capped days
cannot exceed the allowance. The price is that a runaway day blanks the maps
instead of charging for them — the same trade this file makes everywhere else.

## The map style is the tape palette

This is the part that is easy to skip and shows immediately.

Under Leaflet the mixtape look came from a CSS filter over the tile layer
(`--tape-map-filter`: an invert plus a hue rotation). That trick is gone, and it
cannot come back: Google draws its logo and its required attribution into the
same canvas as the streets, so a filter over the map would recolour the credits
too.

The palette now lives in the cloud style attached to the map ID, which is the
only way to recolour a Google map. Until a style is attached, the maps render in
Google's default colours against a mixtape page. Match the style to the tokens in
[`src/styles.css`](../src/styles.css):

| Style element        | Token            |
| -------------------- | ---------------- |
| Landscape / land     | `--tape-surface` |
| Water                | `--tape-slate`   |
| Roads                | `--tape-chrome`  |
| Road casing          | `--tape-hairline-strong` |
| Labels / text        | `--tape-text`    |
| Points of interest   | off — the pins are the only marks this design wants on a map |

A style is per-map-ID, so a second styled ID can be pointed at a staging build
without touching this one.

## Cost, and why the code is shaped the way it is

Dynamic Maps bills **per map instantiation**: 10,000 free per month, then $7 per
1,000. It does *not* bill per pin, per pan, or per script load.

Detour re-renders its whole root on every state change, so a map built per render
would bill a member for filtering a list. `src/maps.ts` therefore keeps each map
instance alive in module state, in a host div it owns, and moves that div between
containers as renders replace them (`LiveMap`). Pins are rebuilt freely; the map
is not. One member's session should cost one or two map loads, not one per click.

Two things to leave alone unless you mean to change the bill:

- **`detachMap` does not destroy the instance.** It lifts the host out of the
  page and clears markers. Replacing it with a real teardown would restore
  per-render billing.
- **The board refits only when its pin set changes** (`savedPinKey`). This is
  also what preserves a member's own pan and zoom across a re-render.

Usage is visible in the Cloud console under Google Maps Platform → Metrics.
